# Studio UX audit, 2026-11-08

Copy of `~/Projects/ai-3d-storymaker/docs/ux-audit-2026-11-08.md`. Screenshots, baselines and tools live in that repository's `docs/ux-audit-2026-11-08/`; other relative paths in this file are from that repository.

The owner's report: "the layouts [are] stuck over there albeit I was trying to use this project's design components". This audit measures every Studio page against the owner's frontend discipline and the house layout rules from aws-agentcore, names why the layouts are stuck, and splits the repair into packages another agent can run on their own. Nothing in the app was changed; this file, the screenshots and the tools beside it are uncommitted.

## Summary

The Studio uses the library's components inside each page, but not the library's page and shell templates. It builds the shell, the rails and the content column itself, three separate times, out of `AppShell` in document mode, `SubNavLayout`, `WorkArea` and about 900 lines of app CSS. That hand-built frame is what reads as stuck: the primary rail never folds (224 px at every width from 760 px up), the section rail is swapped for a dropdown below 1100 px (the opposite of the house rule), no page except the run page has a breadcrumb trail, a 163 px composer sits at the bottom of twelve pages at rest, and the column only fills the window because `studio.css` overrides `AppShell` with a fixed `calc()` height and `overflow: hidden`.

Headline counts, both measured on the same fixture build (29 routes, light and dark, 1440 and 900 px):

| Judge | Cases | Findings | Routes failing |
|---|---|---|---|
| The Studio's own contract (`studio/e2e/studio-ui.contract.json`, engine from the installed ui-components 2.512.0, all states) | 268 | 814 | 11 of 29 |
| The house contract (aws-agentcore `work-ui.contract.json`, mapped to the Studio DOM, resting state) | 116 | 802 violations, plus 184 coverage findings (no trail in the content column) | 29 of 29 |

Of the 802 house violations, 348 are three shell findings repeated on every route (one in-flow shell column, the body font stack, a 14 px project switcher). The other 454 sit on 23 routes. The worst page is the episode record (`#/episodes/:id`): 392 findings under the Studio's own contract, no trail, a 285 px empty "Review movie" card above its content, and at 900 px a tab strip that runs off the column.

## Method

1. Built the working tree's frontend into a scratch folder and started the audit fixture on port 7489 (`tools/serve-fixture.mjs`).
2. Ran the shared ui-dom-audit skill with the Studio's adapter and contract, exactly as `npm run audit:ui` does, plus the episode and run routes (`STUDIO_AUDIT_EPISODE`, `STUDIO_AUDIT_RUN`). Baseline: `~/Projects/ai-3d-storymaker/docs/ux-audit-2026-11-08/baseline/studio-contract-summary.txt` and `studio-contract-by-route.txt`.
3. Ran the house contract against the same build. The house contract binds selectors to the aws-agentcore portal, so `tools/house.adapter.mjs` keeps the Studio adapter's routes and states and rebinds each house alias to the Studio's DOM (`$header` to `app-shell-header`, `$contentColumns` to `.studio-content`, `$trail` to `[data-ui-breadcrumbs]`, and so on). `tools/make-house-contract.cjs` replaces the house shell marker `[data-shell-nav]` with `main` and drops the two Social footer rules, which are aws-agentcore product chrome rather than layout rules for a separate product. Baseline: `baseline/house-contract-summary.txt` and `house-contract-by-route.txt`.
4. Walked every page headless at 1440x900 (light), six pages in dark and four at 900x900 with `tools/probe.mjs`: screenshot, header and rail widths, trail position, title position, first table row, scroll owners, clipped and off-screen elements, and the font sizes of every text run in `main`. Baseline: `baseline/probe-*.json`.
5. Read each screenshot, then traced each finding to its source line.

## Root causes, ranked

1. **The shell is `AppShell` in document mode, forced to fill the window by app CSS.** `main.tsx:464-470` renders `AppShell` without `layout="fill"` and with the NavRail as its `sidebar`, which the library positions `fixed`. `studio.css:60-63` then sets `.studio-app main { height: calc(100dvh - var(--app-shell-chrome-h)); overflow: hidden }`, and five app wrappers restate `display:flex; height:100%; min-height:0; min-width:0` to keep the column scrolling: `.studio-workarea` (`studio.css:57-59`), `.studio-main` from `Playback.tsx:38` (`studio.css:372-379`), `.studio-body` and `.section-desktop` (`studio.css:380-386`), `.studio-primary` (`studio.css:774-780`). The content column sits 13 elements below `main`; a single wrapper without `min-height: 0` stops it scrolling. Two scroll owners stack in one column (`SubNavLayout`'s `[data-subnav-content]` and `WorkArea`'s body, both `overflow: auto`). Below 760 px the CSS undoes the library's own offsets with `!important` and a hard-coded 53 px header (`studio.css:260-299`). This is the literal "stuck": the frame works only while every hand-written wrapper holds.

2. **The cascade is hand-built three times, with the fold policy inverted.** `SectionNavigation.tsx:42-48, 85-125` (rail 248 px), `Audio.tsx:181-186, 547-578` (rail 290 px) and `NewShow.tsx:193, 318, 1596-1600` (rail 248 px) each compose `SubNavLayout` + `WorkArea` and each swap the section rail for a `Select` or `<details>` at `matchMedia("(max-width:1100px)")`, while the primary rail (`NavRail` in the `AppShell` sidebar, `main.tsx:324-349`, width 224 at `main.tsx:467`) never folds. The house rule is the reverse: the primary rail folds to a 44 px strip from three levels deep and below 1180 px, the section rail stays open until 768 px. The library already ships that model (`useRailFold`, `railDepth`, `railBand`, `RailBandProvider`, `RAIL_FOLD_PRIMARY_BELOW`, `RAIL_FOLD_SECTION_BELOW`, `SubNavLayout collapsed`, `SectionLayout railFold`); aws-agentcore wires it in `portal/src/components/shell/Layout.tsx:335-349, 545-549`. At 900 px the episode page gives 224 px to five links and 676 px to the content.

3. **No breadcrumb trail in the content column.** `WorkArea` gets `breadcrumbs` only for an opened work item or run (`main.tsx:601-605`), and renders them above its body, outside `.studio-content`. Every other page uses a `PageHeader` back link instead: `main.tsx:963` ("All episodes"), `PipelineRuns.tsx:181`, `WorkDetailPage.tsx:25`, `WorkHub.tsx:286`. Measured: 28 of 29 routes have no trail, the run page's trail is 8 px left of its title, and the episode title starts 42.75 px down instead of 16.

4. **The composer is a 163 px block at rest.** `PageComposer.tsx:1369-1377` mounts `ConversationComposer` with `presentation="prompt"` and `suggestionsVisible="empty"` inside `ComposerSurface compact`, as the `WorkArea` footer (`main.tsx:607-628`). It takes 163 of 847 px on twelve pages, its surface is 14 to 25 px wider than its column (scrollWidth 982 against 968 on episode pages, 1241 against 1216 on Work) so the right edge is clipped, and its suggestion chips are 11 px (house control.font-size, 224 instances on 23 routes). The three composers disagree: `PageComposer` is "prompt", `EpisodeDraftComposer.tsx:230` and `NewShow.tsx:955` are "document", the last with a formatting toolbar. The library composer already folds (`ContextComposer collapsible`, `collapsedLabel`; the house rule composer.folded.height holds the folded row to 48 px).

5. **Text sizes come from app CSS and from a contract wider than the house scale.** `studio.css` declares `font-size` 51 times across 11, 12, 13, 14, 16, 18 and 22 px, for example `.muted` 13 px (`studio.css:137-141`, used at 22 call sites), `.eyebrow` 11 px `!important` (`studio.css:84`), `.dialogue-row .spoken-line` 18 px (`studio.css:210`), `.take-detail .spoken-line` 22 px (`studio.css:337`). The Studio's contract (`e2e/studio-ui.contract.json`, type.T7) allows [11, 12, 13, 14, 15, 16, 20, 22] and its type.T4 rule requires the 15/13 px ActionRowList profile, which the house contract fails as off-scale. Some sizes are library-owned (tab counts 10 px, composer chips 11 px, avatar initials 12.16 and 9.12 px). The episode Summary shows eight distinct sizes (10, 11, 12, 12.2, 13, 14, 16, 20).

6. **Page bodies are assembled by hand where a template exists.** The episode record is `PageHeader` + `Tabs` in a `.page-stack` div (`main.tsx:959-1000`) instead of `DetailPage`. The library page is a `.library-layout` grid with a `Card` around a `TreeView` (`main.tsx:745-751`, `studio.css:142-160`) instead of `ListRailLayout`. Jobs (`main.tsx:1111`) and Cloud (`main.tsx:1209`) are `PageHeader` + `PageSection` stacks instead of `CollectionPage` and `PageFrame`. `.page-stack` (`studio.css:70-77`, 18 call sites) re-implements the page frame's width and gutter. The Summary tab renders an empty `MediaCollectionCard` titled "Review movie" (`EpisodeSummary.tsx:57-63`) although the board already dropped that placeholder (`EpisodeBoard.tsx:268`). Work Activity stacks the ledger and the saved jobs, which the repository's own `AGENTS.md` forbids.

7. **The header chrome is hand-rolled.** The brand tile and name (`main.tsx:481-490`, `studio.css:20-45`), the "Dark"/"Light" text button (`main.tsx:547-557`), the "Menu" text button for narrow screens (`main.tsx:473-480`), the connection dot (`main.tsx:532-545`, `studio.css:455-465`) where the library has `ConnectionPill`, `.header-actions` (`studio.css:51-56`), and `.project-switch` defined twice with different widths (`studio.css:46-50` and `567-570`). `TenantSwitcher size="sm"` (`main.tsx:496`) gives the 14 px label the house identity rule fails.

8. **Theme colours are raw hex and the tone overrides cover light only.** `main.tsx:442-457` passes hex values for `primary`, `success` and `textMuted` and defines `tones` only when the theme is light, so tags render as tints in light and as solid saturated blocks in dark. The house reference takes colours from tokens only.

9. **Tailwind class names without a Tailwind build.** The app has no Tailwind step and relies on the library's prebuilt CSS, so classes the library never used silently do nothing: `xl:grid-cols-1` (`pipelineRun.tsx:849`, `StudioInspector.tsx:969`) and `max-w-32` (`AssetActions.tsx:101`). The owner's rule (Tailwind v4 through the design tokens) cannot hold until the app either builds Tailwind or stops writing utility classes.

10. **The library has two release lines with overlapping version numbers.** The Studio pins `@connorhoehnslalom/ui-components` 2.512.0, built from the ui-components branch `feat/t20-prompt-plain` (2.508.0 to 2.512.0, forked from 2.507.2; `feat/rows-and-frames` already holds an unreleased 2.513.0). `origin/main` is 2.510.5 under the renamed scope `@connorhoehn/ui-components` (renamed in its 2.509.0) with the voice components. The tag `v2.509.0` points at the branch's row-controls release, not at main's rename. Moving the Studio to 2.510.5 would be a downgrade: main lacks `ModelViewer` and `FrameStrip`, which `ModelPanel.tsx` and `pipelineRun.tsx` use, and `ComposerPresentationContext`. This is why the requested pin upgrade was not made.
