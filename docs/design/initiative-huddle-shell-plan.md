Chat to the huddle must resolve a call-specific conversation with authoritative participant membership. The call lobby also includes unanswered invitees or admits a broader room audience, so none of these is an automatic substitute for the To huddle target. Add a BFF resolver such as `GET /api/calls/:callId/chat` that returns the canonical call-chat channel and current audience. The installed router's channel authorization returns a synchronous boolean; it cannot await `CallStateStore.getCall()`. Maintain a fail-closed membership mirror keyed by call and authenticated connection. ## Synchronized page sharing

Implement page sharing in the BFF using the installed public call-store and gateway interfaces. The gateway already creates the `CallStateStore` passed into `calls()`. Its `getCall(callId)` supplies current participant connection IDs; the router supplies authenticated actor lookup and direct delivery to those connections. A mandatory realtime-modules release is unnecessary.

Page sharing itself uses those existing interfaces. The separate gateway restart defect required the upstream 0.100.2 recovery release described in the integration evidence above; the BFF observes successful public resume/prune operations to replay or finish the associated page state.

Proposed HTTP contract:

| Endpoint | Purpose |
| --- | --- |
| `GET /api/calls/:callId/page` | Read the current acknowledged page snapshot after joining or reconnecting. |
| `PUT /api/calls/:callId/page` | Share a validated page reference with an expected revision. Derive presenter identity, title, and destination on the server. |
| `DELETE /api/calls/:callId/page` | Stop the current presentation with a revision and presenter or host check. |

A snapshot contains the call ID, revision, presenter identity, canonical page kind and identifier, authorized display title and destination, and update time. Keep page state separate from the library's call-store schema and tie its lifetime to the call. Reuse memory and Redis storage conventions already used by the gateway.

Every request checks the current session and grants, intersects the caller's authenticated connections with the active call's participant connections, and checks page access. Recipients receive only metadata they may read. Build routes and titles from allowlisted resource resolvers, and reject client-supplied actors, recipient lists, or arbitrary redirects.

After a successful write, send a versioned `call-page` snapshot to the current authorized participant connections. Fetch on join and reconnect to recover missed updates. Ignore late replies for a previous call or older revision. Clear state on terminal call events and handle the presenter's departure explicitly, including reconnect grace rather than treating a transient socket loss as Leave.

Do not add arbitrary verbs to the existing `call` service: it rejects unknown actions before authorization. If a separate WebSocket service is preferred later, register it through the public `defineFeature` API. Existing document `present` and `call-meta` actions depend on document-specific storage and are not a general page-sharing contract.

Redis state does not turn the current local router into cross-replica fan-out. Retain the established single-router deployment assumption for this work.
