notes: Four defects found on this first pass, all of them things a reader would have drawn a wrong conclusion from. (1) The Gateway panel could not issue a request at all: `GatewayProxyClient` calls `globalThis.fetch` unbound — it stores it as a class field and invokes it as `this.fetchImpl(...)`, which re-binds `this` away from `window` — so Chrome threw "Failed to execute 'fetch' on 'Window': Illegal invocation" before a byte left the page. Node tolerates that and the library's tests run on Node, which is why it shipped. Proved in-page by reproducing the exact pattern against a live gateway: the unbound field throws and never opens a socket, a bound one reaches the network. Both adoptions now pass a bound fetch through the library's own documented `fetch` injection seam; the upstream bug is queued. (2) The same bug was painting the header's gateway health dot RED on every page of every deployment — a permanent false alarm reading "gateway HTTP status: unhealthy" while the endpoint was answering fine. It reads healthy now. (3) The panel could not distinguish "this host is not a gateway" from "the gateway is down", and rendered the raw exception string to the reader; errors are classified into three outcomes now, pinned by 7 tests, the load-bearing case being that a 404 carries NO message because nothing is wrong. (4) The Scores card, above. A fifth thing was removed rather than fixed: a "Masquerade history" card read localStorage `orgiq:masquerade:history`, which nothing in this repo has ever written — and could not have, since `masquerade()` in lib/auth.tsx has no caller anywhere in the portal, so there is no UI that starts a masquerade and no event to record. It was empty for every role in every deployment while telling the reader "Switch roles via the header menu to populate", which is wrong twice over.
