Cause: the list column is the wire's `todayRunCount`, which the server computes as `started_at >= date_trunc('day', NOW())` — the cluster's day, UTC — and that is the same boundary `maxRunsPerDay` is enforced against; the detail footer is `botRunSummary`, which counted the BROWSER's local day. The effect is not cosmetic: it understates how close a bot is to the cap that will refuse its next run, for every viewer west of UTC, every evening. Fixed in portal/src/pages/bots/botsFormat.ts (`isSameLocalDay` → `isSameServerDay`, UTC getters, with the reasoning in the comment) plus a TZ-pinned regression test.
