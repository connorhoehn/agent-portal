One further behaviour worth knowing, observed rather than inferred during this pass: removing a computer server-side does not necessarily keep it removed. `DELETE /api/devbox/boxes/:id` returned `{"removed":true}` and `GET /boxes` then read empty, but a browser still holding this page open re-registered the same box — same id, same label, and its ORIGINAL createdAt — through the ui-components compute fleet mirror it keeps in localStorage (`ui-components.computeFleet.v1`). That is the documented re-adoption path working as designed (it is why `POST /boxes` accepts a caller-supplied createdAt at all), but the consequence is that a delete is only final once no browser still has the Lab open, and a box can reappear carrying an age older than the process that is now tracking it.
