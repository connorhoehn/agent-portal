# Composites queued for the component library

Gaps found while building pages. Each row is a workaround in this repository and what the library should absorb. No row here exempts a file from the component-discipline gate (`scripts/lib/discipline.sh` only honours rows that say a file is composed locally).

| Found in | Gap | Worked round with |
|---|---|---|

| `portal/src/pages/iq/RunPage.tsx` (lane E1) | A read-only "document with a toolbar" for a frozen text (brief, report): the document reader needs a fixed-height parent, so the page wraps it in a sized `Stack`. | `ReadOnlyDocument` in `Stack className="h-[70vh]"`. |

| `portal/src/pages/join/GuestMiloVoice.tsx` (Milo caption) | A spoken caption for an assistant in a call: `SpokenCaption` with `speaker` (name), `mark` (an `AssistantMark` or avatar), `kind` (`'question' \| 'said'`: a question tinted and marked), `speaking` (a speaking chip), `text`, `holdMs` and `onExpire`, in a polite live region, sized to the stage column. `TranscriptOverlay` cannot carry it: it drops every line 3 s after its last update whatever `fadeAfterMs` says, colours speakers with inline hashed colours, and has no kind or speaking state. | A `Card` (`tone="assistant"` for a question, `default` otherwise) holding `AssistantMark`, `T` for the name and the words, and `Chip`s for "Question" and "Speaking"; the hold and the clearing live in `guestMiloCaption.ts`. |
| `portal/src/pages/interviews/board/useBoardFit.ts` (whiteboard) | `CollaborativeExcalidraw` has no way to open zoomed to its content (Excalidraw's `scrollToContent` / zoom to fit), and no `excalidrawAPI` out. A `fitOnOpen` option (fit once the scene first has elements, until the person moves the view) would do it, for the room's board, the record page's snapshots and the kit editor. | `fitBoardView` sends Excalidraw its own Shift+1 "Zoom to fit" a few times after it opens, with the `.App-toolbar` class lifted for that keystroke (Excalidraw 0.18 measures its toolbar in window coordinates, which squeezes the fit of a canvas lower on the page). |
| `portal/src/pages/interviews/board/useBoardFollow.ts` (whiteboard follow) | `CollaborativeExcalidraw`'s `followUserId` mirrors the peer's scroll and zoom, so a follower on a smaller canvas sees only the top-left of the followed view (the room's lead canvas is about 84% of the candidate's, so the right and bottom sixth are cut). Also an `onViewportInput` callback (the person's own pan or zoom) so a host pauses following without listening to the DOM. | `followUserId` as is (mirror); each canvas publishes its size under its own awareness field `ivboardCanvas` (10/s at most); the pause listens for the person's own trusted press, wheel or key inside the canvas wrapper. |
| `portal/src/pages/interviews/ScorecardPage.tsx` (scorecard at a glance) | A star rating: a `RatingInput` variant (or `StarRating`) that draws the scale as stars, set by click or arrow keys, each star's label read by a screen reader, plus a read-only form for a rating or an average (3.5 of 4). | `RatingInput` to set the rating; a read-only `T` (tone warning, aria-hidden) of ★/☆ glyphs beside "3 of 4: anchor" in words. |
| `portal/src/pages/interviews/board/InterviewBoard.tsx`, `pad/InterviewPad.tsx` (board toolbar row) | `DropdownMenu`'s trigger is not in the `Button` family: its `default` trigger is transparent with a grey border and secondary ink, while a `Button size="sm" variant="secondary"` beside it (a pressed/unpressed toggle such as "Following Mateo") is primary-tinted, so a menu and a toggle in one toolbar row never quite match. A `triggerVariant` that renders exactly `Button`'s own `secondary`/`ghost` at the density's size (or a `MenuButton` built on `Button`) would make the row one family. | The `default` trigger (28 px, 12 px semibold, 6 px radius under the compact density) beside `Button size="sm" variant="secondary"` with `aria-pressed`: same box, type and radius, different tint. |
