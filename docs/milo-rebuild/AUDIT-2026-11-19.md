# Audit of the last two days on main (2026-11-19)

Read-only. Scope: the 276 commits since 18 November (343 files, +27,463 lines): the Candidates tenant, Milo, the voice gate, the films, and the library usage. Evidence is `file:line`, commit hashes, and rows of the film reports in `scratchpad/interviews/film/`. Three parallel lanes did the security, UI and code-hygiene reading; I checked their main claims in the code before repeating them. Nothing was run except one pure-function probe (`scratchpad/interviews/audit-probe.mts`).

## 1. Verdict

- **Milo is wrong live because of its design, not its bugs.** A speech-to-speech model that decides for itself when to talk is being used as a wake-word detector, a read-aloud voice and a tool router, with about seven correcting layers on top. The layers fail against each other. More patches will not converge; 127 of the 276 commit subjects are already about Milo.
- **The rest of the work is in much better shape.** The interviews pages hold the library rules (0 inline styles, 0 `<div>`, 0 `<button>` in the 54 changed portal files). The answer key is stripped by allow-list and guest routes are bound to the guest's own invite. No critical security hole was found.
- **The checks did not check the product.** The voice gate runs a copy of the server-line path on trivia questions, by hand, and was never green. The scripted model passes 33 of 33 where live takes pass 28. The rules were tuned on the film's own sentences.

## 3. Milo: why nearly every live use is wrong

**Short answer.** The architecture is not sound. Milo is built on a speech-to-speech model that decides for itself when to talk, and the code uses that model as three things it is not: a wake-word detector, a text-to-speech voice for sentences the server wrote, and a tool router. Each misfit got a correcting layer, and the layers now fail against each other. Nothing in the latest film failed because of one bug; each failure is two layers disagreeing.

### 3.1 The constraint everything else grew from

The provider's Live session has no switch for "speak only when told". The probe tried twelve fields and all were refused (`HANDSFREE-PROBE.md` section b: "the only control is WHAT the session hears"). The interviews plan then added the opposite requirement: in an interview Milo may only say words the server holds (`docs/interviews-tenant-plan.md:59-60`, decisions 9 and 10), and it must say them "on the same live session".

So a model that cannot be told when to speak is asked to read fixed sentences word for word, and to stay silent otherwise. Everything below is machinery to force that.

### 3.5 Is the voice gate measuring the right thing?

No. It measures the plumbing's speed on a path the product does not use.

- Its main scenarios ask trivia the model answers from its own knowledge (expected answers "madrid", "cairo", `scripts/voice-harness/gate-spec.mts:92,156-158`) and score latency percentiles, counts of replies, stray frames and `askedBy` (`gate-spec.mts:241-308`). Only name-last and the two candidate-preface scenarios look at words at all.
- In interviews every answer is a server line through the orchestrator, which the gate's family never produced (`HF-FILM-DIAG.md` line 2: "the gate's family holds nothing, so it only measured relayed model audio").
- The interviews scenarios added later run through a stand-in (`handsfree/gate-interviews.ts`, a `sayFixed` "that mimics the orchestrator's", `hf-real-CHECKPOINT.md`), not the orchestrator.
- It never passed whole anyway: 21 pass / 4 fail, then 40 / 15, then 11 / 7 / 4 skipped (`hf-fast`, `hf-real`, `hf-gate2` checkpoints). The film went ahead on a red gate.
- The scripted session passes 33 of 33 where live takes scored 28 (`NIGHT-STATUS.md`). The mock model behaves ideally, so it proves the wiring and nothing about Milo.

**What "correct" should be scored on**, per turn, on the real policy, through the real entry point:

1. Addressed or not: answered when asked, silent when not.
2. The right action for that person: tool and arguments, or a refusal, by their role.
3. The content is true: minutes within one of the clock; the question text equals the round's question; the introduction is the fixed text.
4. Heard in full, and what was heard equals what was logged and captioned.
5. Speech end to first audio, p50 and p90.
6. No audio over the asker; stop time when talked over.
7. Per call: zero spoken words missing from the log; zero candidate-facing output outside the allow-list.

Items 1 to 3 need no audio. They can run as a text test of a few hundred paraphrases by role in seconds, with sentences the implementer never saw. Keep the audio gate for 4 to 6 only.

## 4. Milo: the target design

**One sentence:** our code owns the turn (who is talking to Milo, and when Milo speaks); a text model with function calling chooses the action; a text-to-speech voice says exactly the text we logged.

```
each mic ─► per-person streaming transcription          (keep: handsfree/listening.ts)
                 │  name heard, hold pressed, or inside the asker's follow-up window
                 ▼
             Floor: idle → hearing(person) → answering → follow-up   (keep, slimmed router)
                 │  the sentence, who said it, their role, the last few lines
                 ▼
             Decide: ONE text-model call with function calling
                 tools offered = policy.toolsFor(person)  (keep: server-tools registry)
                 plus two built-ins: stay_silent, cannot_help
                 ▼
             Act: the server runs the tool as that person (mayAsk, spend, writes) → a line
                 ▼
             Speak: log and post the line, then TTS(line) → relay.  Talked over = stop playback.
```

Why this is simpler and right:

- **Silence is structural.** Nothing is spoken unless Decide returned a line. There is no model audio to mute, hold, or drop, so "unprompted", "muted context", held frames and early verdicts all go.
- **Said = logged = captioned**, by construction. The approved-speech check and its mismatch cuts go.
- **Candidates stay safe, and get understood.** For a candidate, Decide must pick one of `time_left`, `repeat_question`, `cannot_help` (forced tool choice, no free text). The model only classifies; every word the candidate hears is still server-held, which is what decision 10 asks for. "How many minutes do I have?" works because a model maps it, not a regex.
- **Interviewers get tools directly.** One function call with the asker known from the mic. No delegation model, no phrase route, no race between "the phrase ran" and "the model also called it".
- **Work and Social are conversational** by one policy switch: Decide may also return a short free-text answer. Same floor, same voice.
- **Tenant policy shrinks** to: who is admitted and as what role; which tools that role gets; whether free answers are allowed; the instructions; payer; reads; retention.

Latency, honestly: I have not measured this. Estimate from the numbers already recorded: transcription final 0.8 to 1.1 s after speech ends (`hf-real-CHECKPOINT.md` run A/B), Decide 0.3 to 0.6 s, TTS first audio 0.2 to 0.4 s, so about 1.3 to 2.1 s, and fixed lines (introduction, refusals) from cached audio. Today's film is 2.8 to 4.7 s; the speech-to-speech ideal in the probe is 1.2 s. If Work and Social need that last half second, a speech-to-speech session can stay as an optional brain-and-mouth for free conversation behind the same floor, added later and measured. A two-hour probe on the existing harness clips should settle it before any build.

Two things need the owner: decision 9 says "the same live session"; this design keeps the same provider, relay and bar but needs it amended to "the same voice". And the Decide model should be whatever is fastest to first token among the ones already paid for (the provider's small text model, or nova-lite on Bedrock); pick by measurement.

## 7. Security and privacy: what was checked and found safe

Read in code, not exercised live.

- **Answer key.** `candidateQuestion` copies named fields only (`interviews/answer-key.ts:20-27`). Milo's tools read questions only through it (`milo-tools/deps.ts:84-88`). Guest views are their own allow-lists (`interview-invite.ts:91-103`, `invite/room.ts:54-66`). Only the staff room view carries `answerKey`, null without a seat (`room.ts:61-84`). Reveal is lead-only, live, technical, for a chosen question (`answer-key.ts:38-44`), and the board shows the design only after the lead's room inserts it.
- **Guest scope.** The cookie is pinned to one invite and session and re-read per request (`invite/guest.ts:109-162`). The guest floor and hold routes look up the guest's own interview's call, never a caller-supplied id (`interview-invite-milo.ts:73-104`). Board snapshots and reveal exist on staff routes only.
- **Transcripts.** Text only; the listening side stores no audio (`listening.ts:11`). A candidate who declined Milo is never routed to it (`milo-policy.ts:194`). The retention sweep is started (`index.ts:408`) and board snapshots have an eraser (`retention/erasers.ts:195`).
- **OpenAI key.** Read server-side only (`voice/openai.ts`, `openai-transcribe.ts`, `live-session.ts:157`), redacted from socket errors, in no tracked file; only `.env.example` files are tracked. The harness and film scripts take it from an env file.
- **Regexes.** The request regexes are anchored and bounded; none backtrack badly.

## 8. Process: what wasted effort, and what to change

- **The film was the test.** `scripts/demo` is 4,854 lines with 95 waits in the two interview films; 22 commits touched only that folder and 34 mention a film or take. Films cost money and an hour each, catch one sentence per take, and that sentence then went into a regex. *Change:* films are for showing. Correctness is the text scorecard plus five minutes of the owner talking to Milo unscripted.
- **The judge was built beside the product.** The gate was written against a stand-in family while the lanes were building, and nobody noticed it could not see server lines until the film failed (`HF-FILM-DIAG.md`). *Change:* the judge drives the production entry point with the production policy, exists before the lanes start, and a red judge blocks the film.
- **The probe's main result was not acted on.** Probe (b) said the model cannot be told when to speak. The plan built around it instead of asking whether this is the right voice for server-held lines. *Change:* when a probe says the tool cannot do the job, change the tool.
- **Lanes ran out of context mid-fix.** 23 checkpoint files mention a handoff at the context budget; one lane's worktree was removed from under it (`hf-fix1-CHECKPOINT.md:5`); `orchestrator.ts` was edited by nearly every lane (34 commits). *Change:* smaller lanes, one owner per hot file, and split the hot file first.
- **Merges went to main on the light check.** About 2,800 jest tests against 12,162 in the full suite; "the last two fix rounds were NOT separately reviewed" (`NIGHT-STATUS.md`); WIP commits and a six-minute revert on main; 276 commits in two days. *Change:* a branch per feature, the touched area's full suite before merge, no WIP on main.
- **Reviews produced lists, and lists produced patches.** `HF-REVIEW-1.md` has 11 items; all became rule changes. *Change:* the stop rule in F10.
