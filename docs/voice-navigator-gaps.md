# The voice navigator: what is still missing

A read-only sweep of the build that landed on 8 November 2026 (`docs/next-steps.md` §11 "Built") against the design (`docs/voice-navigator-spec.md`), the owner's examples and the owner's framing that every intent is "essentially a search in the backend or an activity in the social app". Nothing here is built; every item is sized so one agent can take it in one repository and prove it without AWS. A separate session is debugging the live loop (tool calls that never reached the browser); the packages below assume the loop works against the scripted session (`MOCK_VOICE=1`) and do not touch `middleware/src/lib/voice` or `portal/src/lib/voice` until that session has landed.

Tags: **fact** = read in this repository or a sibling checkout (file and line named); **decision** = a choice this document makes so the loop can proceed unless the owner overrides; **in flight** = uncommitted work seen in a sibling worktree.

### 2.1 The dock (library first)

**Dock size and type do not match the footer's other controls.** [G1]
Symptom: the ring, the phase pill, the last line and the microphone button read larger than Huddle, Message and the gear beside them. The tokens to match: ring 18px (`size-4.5`), labels `T` xs, controls `Button variant="ghost" size="sm"` with a 16px icon and a text label, no vertical padding. Fix: a `size: 'footer' | 'panel'` prop on `VoiceDock` (default `panel`, so the stories and the reference sheet keep their look), `footer` = sm ring, xs phase label in place of the pill, xs last line, ghost "Voice" / "End" buttons. **in flight**: `~/Projects/ui-components-voice-size` holds exactly this as an uncommitted diff on `VoiceDock.tsx`, `VoiceActivityRing.tsx` and the stories (`SIZE.sm` to `size-4.5`, `size="footer"`), with no release yet. Repo: ui-components, release 2.510.1; then the portal passes `size="footer"` (`VoiceFooterPane.tsx:234-249`) [G17]. Acceptance: a `FooterListening` story; a DOM test that `[data-voice-dock][data-size="footer"]` has no element taller than `--ui-control-sm` and no `text-sm`; the portal's type-scale e2e (`portal/e2e/app-type-scale.spec.ts`) passes with the dock mounted. Model: Sonnet. Estimate: 2h (finish, test, release).

### 2.4 Money

**Delegated-model tokens are not metered.** [G11]
Symptom: a session's ledger row prices seconds only (`middleware/src/lib/voice/ledger.ts:9-16`); the `gpt-6-luna` tokens V1 measured (1,060 in and 20 out per call, spec §1) are billed by OpenAI and recorded nowhere. Root cause: the client drops the nested `response.completed.response.usage` (`portal/src/lib/voice/client.ts:110` keeps only the response id), the close body has no token field (`routes/voice.ts:222-230`), and the price registry has no OpenAI model, so `estimateUsageCost('gpt-6-luna', …)` is `null` (`middleware/src/lib/pricing.ts:115-117`). Fix: the client sums `input_tokens`, `output_tokens`, `cached_tokens` per session; the close posts `{ seconds, delegated: { inputTokens, outputTokens, cachedTokens, responses } }`; the middleware prices them with `estimateUsageCost(cfg.delegationModel)` and books a second ledger row (`source: 'voice_session'`, `sourceId: `${id}:tokens``, `trigger: 'voice-delegation'`), basis `estimated`; `gpt-live-1` per-minute and `gpt-6-luna` per-token prices enter the price table's defaults with `VOICE_DELEGATION_USD_PER_1M_INPUT` / `_OUTPUT` as the override. Until the sideband lands, these figures come from the browser like the seconds do, and are bounded (tokens per response capped at 50,000, responses at the session's tool-call count plus one). Repo: aws-agentcore. Acceptance: the mock script's two `response.completed` frames (`openai.ts:219,224`) settle to 2,254 input and 48 output tokens; the ledger shows two rows per session; `docs/spend-map.md` gains the voice path (today it has none). Model: Opus. Estimate: 4h.

**Seconds are trusted from the browser.** [G12]
Symptom: the close takes `seconds` from the dock, floored at 15 and capped at wall time plus a minute (`routes/voice.ts:226-230`); a dock that lies low pays less, one that dies pays `unknown`. Root cause: the middleware never attaches to the session; `lib/voice/openai.ts` has mint and hangup only (`:152-182`). Fix: on a real mint the middleware opens the sideband `wss://api.openai.com/v1/live/sessions/{id}/attach` with the key (spec §1, verified), one socket per live session in the minting process, and records `session.usage.updated.usage.seconds` (cumulative), `session.closed.usage.seconds` and every nested `response.completed.response.usage` into `voice_sessions.provider_seconds`, `provider_tokens_in`, `provider_tokens_out` (additive columns); the close and the reaper prefer the provider figure (basis `reported`) and fall back to the dock's (basis `estimated`) only when the sideband never connected or the replica died; the reaper hangs up and reads the final usage from the same socket when it can. The attach is best effort: it never blocks the mint, never holds the key anywhere but that module, and is skipped under `MOCK_VOICE`. Repo: aws-agentcore. Acceptance: a fake sideband in the route test delivers usage 56 s while the dock posts 30 s, and the row says 56 `reported`; with no sideband the row says 30 `estimated`; the reaper's `unknown` case stays when neither exists. Model: Opus. Estimate: 5h.

**Daily minutes.** [G13]
Symptom: the owner's Q2 is open; today a session holds p75 × rate against the user's monthly budget (`routes/voice.ts:66-70,100-104`; the budget is monthly, `providers/user-budgets.ts` DE-54). ## 3. Decisions on the three open questions

**Q1, tenants.** **decision**: every tenant gets the dock, with reads and navigation only outside orgiq and social. `VoiceNavigate` goes into every role of the assessment, pipelines and access seeds; `toolsForTenant` offers `navigate` (that tenant's page ids), `search_records` (that tenant's index types) and `access_request_status` (plus `approvals` in access) and nothing that starts a machine, runs a command or posts. Reasons: the tenant is fixed at mint and every tool is tenant-scoped (`catalogue.ts:273-279`, `tools.ts:593`), so cross-tenant stays closed; the reads cost nothing beyond the voice session itself; the tenant searches already exist with their own gates (`index.ts:323-374`); and a research platform should not ship a dock that three of five products cannot see. The machine and people tools stay where their routes are.

**Q2, own minutes or the shared budget.** **decision**: both, with the minutes cap as a config whose default never blocks a local run. The hold against the user's monthly budget stays (it is the one chokepoint for dollars and already answers 402/409 with the confirm flow); on top of it `VOICE_DAILY_MINUTES=60` per user per UTC day, `0` to disable, enforced at mint from the session rows the middleware already keeps. Reasons: voice bills idle time at a flat rate while a user forgets an open dock, which a dollar budget only notices at month scale; minutes are what the dock can say back ("about 20 minutes left today"); 60 minutes is $3 a day at the README rate, cheap enough that the default never gets in the way, and the mock session is excluded so `dev:mock` is never capped. The spend-map and the budget page show voice as its own line because the ledger rows carry `source: 'voice_session'` already.

**Q3, the batch start.** **decision**: one card for the batch, capped at three new computers per call (`VOICE_START_COMPUTER_MAX`, default 3), and only initiatives in the user's `scope=mine` list (as now, `actions.ts:156`). A request for more is answered with the first three by recent activity and a spoken "I started three; say the next ones to continue". Reasons: each box bills idle time until stopped (`actions.ts:148`), the card must list every name it will start, and three names fit the card and the voice; a profile-based cap would be invisible to the user and the profile is the initiative's choice of image, not a permission. Already-running boxes are reused and do not count (`actions.ts:164-170`).

## 5. How to verify end to end without AWS

Run the middleware with `npm run dev:mock` (no `OPENAI_API_KEY` in `middleware/.env`, so `config.ts:75-76` sets `MOCK_VOICE=1`) and the portal with `VITE_VOICE_NAVIGATOR=1`: the mint answers the scripted session (`routes/voice.ts:129-131`, frames from `lib/voice/openai.ts:202-232`), the dock runs listening, executing, speaking and ended, the tenant's `MOCK_CALLS` tool runs against the mock routes, `/events` writes a row and `/close` settles the hold, all visible in the middleware log as `voice-session-minted`, `voice-tool-calls` and `voice-session-closed`. The same loop runs headless under `node --test` through `portal/src/lib/voice/__tests__/voiceHarness.ts` (virtual clock, fake fetch, the middleware's own catalogue loaded by path) and `middleware/src/routes/__tests__/voice.test.ts`. For the wire shapes against the real API, `scripts/voice/probe-middleware-body.mjs` starts a Live session over the primary WebSocket with exactly the body the middleware mints, speaks WAV utterances into it, answers each function call from the mock middleware's `/api/search` and records every frame to a JSONL with the key redacted; one toggle per run isolates a suspect (`--dry` prints the session object with no call). For the browser leg, a Playwright spec in `portal/e2e` with `launchOptions.args` `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` (the pattern of `huddle-media-real.spec.ts:11`) against `MOCK_VOICE=1` clicks `shell-voice-dock-start`, waits for `data-phase="executing"` then `"ended"`, asserts the turn strip shows the tool call as `done`, and reads the `/close` request body from the network log to check the seconds were posted once; the mock mint's SDP is inert (`openai.ts:235-238`), so no media is negotiated and the fake microphone only satisfies `getUserMedia`.
