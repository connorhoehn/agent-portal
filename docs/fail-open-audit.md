# Fail-open audit — defaults that decide security when nothing is set

2026-11-07. Read-only pass over the current `main` of twelve repositories, after today's hardening releases
(distributed-core 0.51.1, managed-nosql-store 0.13.0, realtime-modules 0.146.1, live-video-streaming 2.0.0,
realtime-examples 0.2.4, platform-api 0.1.4, service-runtime 0.7.1, message-queue 0.6.5, event-catalog 0.10.3,
aws-agentcore f989bd4e, ui-components 2.500.3). Every row was read in source, not exercised against a running
system. "Default" is the behaviour with nothing set: no env, no options, no hooks. "Dev flag = yes" means the open
path already needs an operator to set a dev-only switch; a bare `NODE_ENV !== 'production'` does not count.
Verdicts: **fine** (closed, or explicit opt-in), **needs a flag** (open path must require `INSECURE_DEV_MODE`),
**needs fail-closed** (no flag should open it). The middleware rows are pinned by
`middleware/src/lib/__tests__/fail-closed-startup.test.ts` (section 3). Companion: `docs/next-steps.md` §"Cross-cutting" item 1.

*Status, 9 November 2026:* the aws-agentcore rows fixed since this audit carry their commit in the verdict column. The realtime-modules "needs fail-closed" rows are still open (tracked in realtime-modules). `docs/next-steps.md` §10 "Still open" has the current list.

## 2. The convention: one `INSECURE_DEV_MODE`, read through one helper

| rule | statement |
|---|---|
| the flag | `INSECURE_DEV_MODE=true` (trimmed, lower-cased). It is the only variable that may open a security default. |
| the helper | `insecureDevMode(env)` = flag on **and** `NODE_ENV !== 'production'`, logs one loud line at start, reported by `/health` as `insecureDevMode: true`. Publish it from `@connorhoehn/service-runtime` (`src/config/insecure-dev-mode.ts`) — middleware, platform-api, realtime-examples, message-queue and event-catalog already depend on it; LVS copies the six lines if it will not take the dependency. platform-api's `src/lib/insecureDevMode.ts` is the text to lift. |
| boot gate | Any dev shortcut set without the flag refuses to start (platform-api `assertSkipAuthAllowed`, realtime-examples `skipAuthStartupDenial` with its loopback-bind rule are the models): `SKIP_AUTH`, `LVS_AUTH_BYPASS`, `SERVICE_AUTH_DISABLED`, `SERVICE_AUTH_DEV_OPEN`, `MNS_INSECURE_CLUSTER`, `AUTH_DEMO_MODE`, `ALLOW_INTERNAL_IMAGE_FETCH`, `WSG_ORG_GATE_ENFORCE=false`, `LOBBY_AUTHORITY_REQUIRED=false`, `ALLOWED_ORIGINS=*`, `COGNITO_REQUIRED=false`, `WSG_ACCEPT_QUERY_SESSION_TOKEN`. Then delete the second-tier names (`LVS_AUTH_BYPASS`, `SERVICE_AUTH_DEV_OPEN`, `MNS_INSECURE_CLUSTER`, `AUTH_DEMO_MODE`) once callers moved. |
| missing secret / key / hook | refuse to start, or answer 503, unless `insecureDevMode()`. `NODE_ENV !== 'production'` is never again a security predicate (still set `ENV NODE_ENV=production` in every runtime image: middleware, portal, realtime-examples, message-queue lack it). |
| libraries | realtime-modules, distributed-core, service-runtime, pipeline-runtime and managed-nosql-store's classes never read the env.
